## 1. P0：立即可做（低风险，纯增益）

### 1.1 `surviveUnits/bornUnits` 类型化

- **现象**：本仓把怪猎对决（EnemyDuel）结算请求里的两个字段标成不读的 JSON：
  - `app/game/modules/activities/shared/activity.schema.ts:221-225`（`surviveUnits: z.array(z.json()).optional()`、`bornUnits` 同）
  - 同文件 `:259-266`（另一处同类请求）；类型侧 `app/game/modules/activities/shared/activity.ts:470-471, 480-481`（`unknown[]`）
- **obs 提供真值**：`OpenBachelorInsight-master/src/inject/reader.ts`（hook `Torappu.DataCenter.EnemyDuelDataCenter.AddTeamData`，读 `teamLeft/teamRight` 的 `enemyId`+`count`，**右侧计负数**）以及真实数据 `data/*.jsonl`：
  `born_units: [{round, leftUnitIds:{enemyId:count}, rightUnitIds:{...}}]`、`survive_units: [{round, unitIds:{enemyId:count}}]`；对局另带 `stage_seed`、`round_0..9_seed/victor`（1=左胜、2=右胜）。
- **建议做法**：新增 zod 子 schema（`{ round: number, unitIds: record(number) }` 与 `{ round, leftUnitIds, rightUnitIds }`），替换两处 `z.json()`，并把 `activity.ts` 的 `unknown[]` 收敛为具体接口。
- **收益**：① 直接消一条类型债；② 解锁「服务端按存活单位/回合结果做结算校验或统计」的前提；③ 为 ④ 的会话服结算（SS 的 `RoundSettle`/`FinalSettle` 需要同一语义）打底。
- **验收**：`pnpm run typecheck:tests` + 针对该 schema 的单测（现有 enemyDuel 用例文件内追加，勿新建文件——见 AGENTS 测试性能约束）。

## 2. P1：中期（需要设计，但本仓已有先例可抄）

### 2.1 EnemyDuel 实时会话服（SS 移植）——本次分析最大的增量

**为什么需要**：本仓怪猎对决只有 HTTP 侧（`app/game/modules/activities/enemyDuel/router.ts`，8 个端点：singleBattleStart/Finish、startMatch、queryMatch、createTeam、joinTeam、multiBattleStart/Finish），而 `enemyDuelServerAddress()`（:150-152）返回的是**本服自己**的 `host:PORT`，客户端拿到 address+token 后去连的是一个不存在的实时对局服。obs 的 `OpenBachelorSS` 就是那块实现。

**两边已经对得上的部分**（说明移植成本主要在编解码，不在对齐语义）：
- `serverToken = "${modeId}|${curStage}"`（本仓 `router.ts:264`）与 SS 的 `getModeIDStageID`（`internal/game/game.go:820`）**逐字一致**；`createTeam` 用 `${modeId}|create`（:285）。
- 本仓 `config` 目前**没有**会话服端口字段（`app/core/config/index.ts` 只有 capture 的 `gatewayPort`），需要新增。

**in-repo 先例（照抄结构即可）**：`app/game/modules/activities/arkhub/` 已经在**游戏模块内**跑了一个私有 TCP 服务：
- `gateway/local.ts:1-30` —— `net.createServer` + 长度前缀帧切分 + 连接生命周期 + 帧日志；帧格式 `[4B 大端总长][4B mainID][8B subID][protobuf]`（`docs/arkhub-gateway-protocol.md`）。
- `gateway/router.ts`（FrameRouter + 上下文契约）、`gateway/handlers/{session,play,shop}.ts`（按域拆 handler）、`gateway/codec.ts`（线级编解码）。
- `public.ts` 收敛对外出口；`app/server.ts:278-279` 在 `main()` 里 `startArkhubLocalGateway(...)` 启动。
> 也就是说：**「游戏模块自带 TCP 服务 + 二进制协议 + 帧路由 + public 出口 + server.ts 启动」这套骨架本仓已经跑通一遍**，EnemyDuel 会话服把它平移到 `enemyDuel/session/` 即可。

**需要照搬的协议契约（来自 SS，行号为 SS 内文件）**：

| 内容 | 出处 | 要点 |
|---|---|---|
| 帧格式 | `pkg/protocol/protocol.go:9-11,25-38` | `[uint32 BE payload 长度][uint32 BE 消息类型][payload]`；读侧限长 1 MB |
| 字段编码 | `pkg/contract/payloads.go:141-201` | 字符串 = uint16 长度前缀；切片 = uint16 元素数；`maxStrSize=1024`/`maxSliceSize=128` |
| 消息类型号 | `pkg/contract/messages.go:11-34` | S2C 11 个（2/204/206/210/212/214/220/224/602/702/714）、C2S 10 个（1/201/203/211/215/217/219/221/223/601）；未注册降级 `UnknownMessage` 透传 |
| 核心结构 | `payloads.go:706-713,602-611,1366-1377,1570-1574` | `ClientState{State,Round,ForceEndTs,SrcEntryData,BetList,LeaderBoard}`、`RoundLeaderBoard{OldMoney,NewMoney,MaxRound,Streak,Result,Bet,ShieldState}`、`TeamStatus{State,Owner,TeamStateEndTs,StageID,ModeID,Players,SceneID,Address,Token,AllowNpc}`、C2S `Join{PlayerID,SceneID,Token}` |
| 状态机 | `internal/game/game.go:162-376,434` | 100 ms tick；`Waiting`(等 ready/30 s 超时) → `Entry`(3 s) → `Bet`(20 s) → `Battle`(150 s) → `Settle`(10 s) → `Finish`(10 s) |
| 规则 | `game.go:521-539,663-700,721-750,566-588` | ≤8 人、10 round、初始 10000 币、彩池 `roundMoneyMap` 2000→50000、按 `reportSide` 多数票判胜负、超时 `0b11` |
| 单人模式 | `game.go:797-818` | `single_player` 时所需人数压成 1 → 单人也能开局（建议本仓首版就只做单人） |
| 验收基准 | `cmd/parser/main.go:26-63`、`pkg/contract/payloads_test.go:15,45` | 抓包 round-trip 字节级校验 + 现成字节样例，可直接变成 vitest 断言 |

**建议落地骨架**：
```
app/game/modules/activities/enemyDuel/session/
  codec.ts        // 帧读写（Buffer.writeUInt32BE / readUInt32BE + uint16 前缀字符串/切片）
  messages.ts     // 21 个类型号常量（照 messages.go:11-34）
  payloads.ts     // 按 payloads.go 逐字段 marshal/unmarshal
  game.ts         // 六态状态机 + 下注赔付（照 game.go）
  server.ts       // net.createServer + 会话表 + 心跳/超时回收（照 arkhub/local.ts 结构）
app/game/modules/activities/enemyDuel/public.ts   // 收敛出口
app/core/config/index.ts                          // 新增 multiplayer.{enabled,port,singlePlayer,waitSec}
app/server.ts                                     // main() 内启动（参照 :278-279）
```
- `router.ts:150-152` 的 `enemyDuelServerAddress()` 改为读新 config；
- 先用 `singlePlayer: true` 打通 `Waiting→…→Finish` 全链路，再做多人/下注；
- 单测：用 `payloads_test.go` 的字节样例做编解码断言；状态机用假时钟推进。

**风险与边界**：
- 协议正确性：SS 是逆向实现，优先照抄字段序与整型宽度，**不要「顺手优化」**；上线前用真实客户端抓一次 `enemyDuel` 会话字节做 round-trip 比对。
- 版本：SS 的形态对应 2.7.x，本仓当前客户端 2.7.71，需抓包确认类型号未变。
- **不要混淆**：本仓 `app/game/modules/multiplayer/` 是 ActMultiV3 多人合作（21 个占位端点），与 EnemyDuel 是两套协议；SS 的 8544 icebreaker 在 obs 里是空壳（无任何消息定义），**没有可移植内容**。

### 2.2 免 root Android 注入链（C + G）

**本仓现状**：PC 侧有 `scripts/frida-observe.ps1`（停 ACE 后 spawn `Arknights.exe` 注入 `hook/observe-assetbundle.js`）；APK 侧有 `scripts/apk-lua.ts`（往官方 APK 里注入 Lua bundle，并在 `:457-468` 自动打开 `assets.enableMods`）；抓包有 `scripts/proxy-harness.ts`。**缺的是「不 root 的手机/模拟器 + frida-gadget」这条**。
**可借鉴的具体做法**（obs，均只需少量胶水代码）：

| 借鉴点 | obs 出处 | 说明 |
|---|---|---|
| `adb reverse tcp:{8443,8543,8544}` + `adb forward tcp:27042→gadget_port` | `C src/launcher/openbachelorc/adb.py:221-252` | 让设备侧 `127.0.0.1` 直达 PC 上的本仓，比 Fiddler 省事（CF 只在 PC/不 root 场景需要） |
| frida-server 二进制改名伪装 | `adb.py:106-108` | 把 `frida-agent-<arch>.so` 改名为 `florida-123-<arch>.so`，避免被按进程/文件名声纹识别 |
| gadget 双模式 | `G main.py:105-127` | `listen 127.0.0.1:10443`（配合 adb forward）或 `script-directory /sdcard/openbachelor`（脱机注入，参数走 `parameters`） |
| 随 APK 加载 gadget | `G smali.patch:1-16` | 在 `com/u8/sdk/U8UnityContext.<clinit>` 加 `System.loadLibrary("florida")` |
| 改包名共存 | `G main.py:177-249` | 改 `applicationId` + 删 provider/permission + 重签名，与原版 APK 并存 |
| 注入配置协议 | `C inject.py:52-54` | `post({type:"conf",k,v})` 逐条下发；本仓 `hook/main.ts:225` 目前是把 `serverUrl` 写成脚本常量（`http://<本机IP>:8443`），可借鉴改成运行时参数 |

**红线（只文档化，不入产品代码）**：`G misc.patch`（阉割 MTP 反外挂）、`java.js`/`native.js` 的证书链与签名校验绕过（`TrustManagerImpl.checkTrusted`、`BouncyCastleCertVerifyer`、`VerifySignMD5RSA`、`android_dlopen_ext` 屏蔽 `msaoaidsec`/`anogs`）。本仓已有 `scripts/apk-audit.ts` 与 `docs/apk-security-audit.md` 的安全审计路线，注入链只作为**开发/抓包工具**记录在 `docs/`。
> 顺带一条对照：`hook/main.ts` 里 `Networker.get_overrideRouterUrl`（:277-283）与 `CryptUtils.VerifySignMD5RSA`（:288-289）**都处于 262-338 的块注释内、当前未生效**（活跃的只有 `SDKConst$UrlInfo.getRemoteUrl` :238/:245 与 `Il2Cpp.dump("d.cs")` :257）。若走 PC attach 抓官服流量，这段是现成可解注代码。

## 7. 附录 B：复现命令

```bash
# 1) 抽出 obs 的历史 FBS 做交叉校验（本机无 unzip/7z，用 python 标准库）
python3 - <<'EOF'
import zipfile, os
z = zipfile.ZipFile('reference/obs/OpenBachelorM-master.zip')
p = 'OpenBachelorM-master/fbs/2.7.61/'
for n in z.namelist():
    if n.startswith(p) and n.endswith('.fbs'):
        os.makedirs('tmp/obs-fbs/2.7.61', exist_ok=True)
        open('tmp/obs-fbs/2.7.61/' + n.rsplit('/', 1)[-1], 'wb').write(z.read(n))
EOF
pnpm run schema:crosscheck -- --fbs tmp/obs-fbs/2.7.61

# 2) 抽取 obs 任意项目源码（跳过 res/data/pic 等大目录）
python3 - <<'EOF'
import zipfile, os
zf, prefix, dst = 'reference/obs/OpenBachelorSS-master.zip', 'OpenBachelorSS-master/', 'tmp/obs-analysis/SS'
z = zipfile.ZipFile(zf)
for n in z.namelist():
    if n.startswith(prefix) and not n.endswith('/'):
        out = os.path.join(dst, n[len(prefix):]); os.makedirs(os.path.dirname(out), exist_ok=True)
        open(out, 'wb').write(z.read(n))
EOF
```
