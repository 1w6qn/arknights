## 3. 重构后：目标布局

```
app/game/modules/activities/arkhub/
├── public.ts                 # 唯一门面：domain / session / capture 三组星导出（28 行）
├── router.ts                 # HTTP 薄壳（/activity/arkhub/*）+ rootRouter（/pixelArt/review）
├── logic.ts                  # HTTP handler 实现
├── domain/                   # 玩法域（HTTP 与网关共用；不 import session、不 import ops）
│   ├── state.ts              # 状态形状 / ARKHUB_ACT_ID / ARKHUB_ERR / 计数器事件 / 币同步与商店币引用
│   ├── dex.ts                # ARKDEX 寻迹 / 道具 / 交换 / 每日货架
│   ├── pixel.ts              # 像素存储（落盘 + 索引 + 发布/收集计数）
│   └── pixel-format.ts       # 24×24×3 RGB 格式常量 + 校验（自 ops 收回，唯一事实来源）
├── session/                  # ARK_HUB 长连接网关会话（对齐 enemyDuel/session 分层）
│   ├── messages.ts           # 帧 subID / 返回码 / 段前缀 / 广播帧表（188 行，唯一来源）
│   ├── codec.ts              # 线级编解码（varint / 字段 / 整帧 / 帧读取器）
│   ├── contract.ts           # 跨层契约（连接状态 / 处理上下文 / 帧形状 / 启动回调选项）
│   ├── dispatch.ts           # 帧分发（main → full → low32 → fallback）
│   ├── handlers/             # 业务：hub（登录/场景/交互/引导）、play（捕捉/对局/生物/交换）、shop（商店/道具/像素）
│   ├── server.ts             # TCP 传输：监听 / 端口避让 / 活跃态 getter
│   └── bindings.ts           # 启动绑定：createArkhubSessionBindings(playerPort)（24 个回调，308 行）
└── capture/                  # capture 模式官服网关适配（不属于运行时会话，故不入 session/）
    ├── proxy.ts              # 30000 转发器 + enterHall 改写 + 抓包记录注入
    └── protocol.ts           # 抓包帧解析 / 字典（拆分后仍单文件，供 ops/scripts 解析存量记录）
```

## 6. 门禁与约束

### 6.1 新增守卫（`tests/unit/architecture/module-boundary.test.ts`）
- **R5**：`app/game/**` 不得 import `app/ops/**`。落地后全仓仅剩 `modules/system/plugin-heartbeat.ts → @plugin/index`
  一条既有边（插件宿主入口），已登记 `EXEMPTIONS` 并附 reason；arkhub 的历史违规已从根上消除。
- **R6**：`app/ops/**`、`scripts/**`、`tests/**` 引用 `app/game/modules/activities/arkhub/**` 必须落在
  `.../arkhub/public`（模块内自引用豁免；相对路径引用同样拦截）。
- 两条规则均带负样本自证用例（含「public 门面放行」「模块内自引用放行」「非 arkhub 模块不受影响」）。

### 6.2 棘轮按路径记账（本次踩到的约束）
`type-debt-ratchet` 把 rename 视为「新增文件」，因此纯位移必须同步处理基线：
- `type-debt-baseline.json`：删除 6 条旧 arkhub 路径，新增
  `capture/proxy.ts`（unknown 6）与 `tests/…/gateway/gateway.test.ts`（unknown 1），总额按明细重算（unknown −17）；
- `excel-singleton-baseline.json`：`activities/arkhub/arkdex.ts` → `activities/arkhub/domain/dex.ts`（计数 1 不变）；
- 未使用 `--write --expand-scope`（该通道语义是扫描范围扩容）；未放宽任何既有文件的计数。

### 6.3 保留的边界 `unknown`
`capture/proxy.ts` 的 6 处 `unknown`（转发器 sink 的 `extraMeta`/返回值、`adaptArkhubEnterHallResponse` 的
`payload` 入参/返回、endpoint/port 探测）是 axios 响应体与 ops 记录端口的**真实边界类型**，按仓库
`docs/type-system-audit.md` 的策略保留在棘轮内，不强行 cast。

## 7. 决策记录与剩余待办

### 7.1 明确「不做」的决策（附理由）
| 项 | 决策 | 理由 |
|---|---|---|
| `unlockActivity` 播种下沉到 `arkhub/domain/seed.ts` | **保留在 `activities/shared/unlockActivity.ts`** | 播种是跨活动的 playerdata 引导流程，`shared` 已是活动族共享层；而 `arkhub/public.ts` 门面会连带 `session/server.ts`（net）与 `capture/proxy.ts`（net/fs）进入 **kernel 启动路径**（`kernel/inventory.ts → shared/unlockActivity`）。为一个 `type === "ARK_HUB"` 分支引入 TCP 模块图得不偿失。若将来要下沉，应先给 arkhub 拆出**无网络依赖的 domain 门面**（`public-domain.ts`），再同步扩守卫 R6。 |
| `medal/medal.ts` 的 3 个 `ActivityArkhub*` 模板下沉 `medal/templates/arkhub.ts` | **保留在 `medal.ts`** | medal 模块目前是单文件注册表（模板 + dispatch 表同文件，无分活动目录先例）；为单个活动引分组只增加间接层，收益为负。 |
